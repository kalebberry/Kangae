# Stage 01 — Understand

## Purpose

Establish a shared and correct model of the problem before solution work begins.

## Reads

- developer request
- relevant code, files, tickets, logs, or documentation
- `KANGAE.md`
- prior ICM artifacts when revisiting this stage

## Responsibilities

Capture only what is needed to understand the task:

- desired behavior
- current behavior
- constraints
- known facts
- unknowns
- assumptions
- available evidence
- success criteria

Kangae applies here: preserve developer reasoning and do not jump to implementation merely because a likely fix is visible.

## Produces

`output/problem.md`

The artifact should be concise and easy for the developer to correct.

## Checkpoint

Before routing onward, there should be enough shared understanding to answer:

- What are we trying to change or learn?
- What do we actually know?
- What remains uncertain?
- What would count as success?

If those answers are unclear, remain in Understand.

## Routes to

Usually:

- `02_think` when reasoning or hypothesis formation is useful
- `03_attempt` when the solution is straightforward and well understood
- `05_review` when the task is primarily evaluation
