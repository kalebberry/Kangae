# Kangae Skill — Engineering Journal

## Purpose

Create a concise reflection artifact after meaningful engineering work.

The journal is for review and learning, not passive logging.

Kangae remains the governing protocol.

## Trigger

Use after meaningful:

- debugging,
- unfamiliar technical work,
- architecture decisions,
- code reviews,
- study sessions,
- repeated mistakes,
- breakthroughs.

Do not journal every trivial action.

## Workflow

Prefer:

**WORK → REFLECT → DRAFT → HUMAN REVIEW → REVISE**

### Capture

- Date / Session
- Problem
- Initial Thinking
- What I Tried
- Evidence
- What Changed My Mind
- Decision
- What I Learned
- Still Unclear
- Next Time

Use `JOURNAL-TEMPLATE.md` when available.

## Rules

The draft must:

- use observable work and discussion,
- distinguish facts from interpretation,
- preserve uncertainty,
- avoid inventing motivations,
- avoid reconstructing hidden chain-of-thought,
- remain concise enough for the developer to review.

The developer should correct the draft before treating it as final.

## Completion

The workflow is complete when the journal reflects the developer's actual understanding and contains useful lessons worth revisiting.
